# ChromeDevToolsAutoAllow 使用说明

首发版本：**1.0.0**。适用于 Windows x64 / .NET Framework 4.8。

## 启动

把发布 ZIP 解压到有写权限的目录，运行 `ChromeDevToolsAutoAllow.exe`。不需要安装；图标已内嵌。新目录不含设置文件时，默认只检测、不操作按钮。

如果 ChromeConsentGuard 旧版仍在运行，请先从旧版托盘退出。新旧版本共享单实例互斥锁，不应同时运行。

## 托盘菜单

| 项目 | 行为 |
| --- | --- |
| 状态 / Status | 显示当前模式、最近结果、统计、日志和设置位置 |
| 启用自动允许 10 分钟 | 用户确认后临时启用；取消之前保存的永久选择 |
| 启用自动允许（永久） | 用户确认后保存选择；正常重启会恢复 |
| 立即停止自动允许 | 立即关闭并保存关闭状态 |
| 立即检查一次 | 检查当前窗口；遵循当前模式，不会清除同按钮去重 |
| 退出 | 结束进程；不清除以前保存的永久选择 |

**风险**：弹窗不能证明请求者身份。自动模式可能批准其他本机程序发起的同类远程调试请求。只在你了解并信任的开发环境使用，不使用时停止。

永久模式不代表程序退出后仍然工作，也不代表开机自启。单次运行最多尝试 256 个不同按钮，达到上限后保护性停止。停止程序不会撤销 Chrome 已建立的调试连接。

## 结果解释

- `INVOKE_RETURNED`：按钮接口已经返回，**不是授权成功证明**。
- `DIALOG_DISMISSED`：原弹窗不再可用，**不是 MCP 连接成功证明**。
- `UNCONFIRMED`：弹窗仍存在或状态无法可靠读取；自动模式停止并提示手动处理。

一次输入后有 4 次有限只读检查，累计等待约 3.25 秒。不重复点击，不追加鼠标或键盘操作；UIA 提供方阻塞时，这不是硬超时。

## 设置与隐私

`settings.ini` 和 `logs/` 位于 EXE 同目录。设置绑定 Chrome 完整路径。新发布包不会携带个人设置。

若保存关闭状态失败，应在重启前处理错误；旧永久设置可能尚未覆盖。不要把自己的设置和日志直接上传到公共仓库。

## 命令行

```powershell
# 本次只检测，不删除已保存的设置
.\ChromeDevToolsAutoAllow.exe --observe

# 限时后台检测，不恢复自动模式
.\ChromeDevToolsAutoAllow.exe --no-tray --seconds 60

# 指定 Chrome 路径与日志
.\ChromeDevToolsAutoAllow.exe --observe --chrome-path "C:\Program Files\Google\Chrome\Application\chrome.exe" --log ".\logs\observe.log"
```

命令行不提供开启永久自动允许的开关。

## 从旧版本迁移

推荐先在旧版停止自动允许并退出，再解压新包。新版新目录默认仅检测；不要自动复制旧版已启用的个人设置。

如果选择保留自己的旧设置，设置格式相同，但须自行了解保存模式会恢复。此版没有加入新的授权方式；只是正式命名、工程化和发布整理。
